# Plan

## Goal

恢复人口普查区分析，使任意受支持时间范围下都能选择普查区，并在选择后显示统计摘要、图表和事件明细；固定快照仅负责可用时的全市分级设色，不再阻断选择。

## Scope

- 解耦普查区可点击边界与犯罪快照分级设色。
- 让普查区选择进入事件刷新链路，并按所选普查区多边形过滤事件点和明细。
- 区分“未选择普查区”“当前筛选无事件”“全市分级快照不可用”三种状态。
- 扩展现有契约测试与浏览器验证，不引入新依赖。

## Sources of truth

- 当前浏览器复现与 URL 状态。
- `src/routes_crime/`、`src/map/`、`src/api/crime.js`、`src/utils/sql.js` 的现有实现。
- `public/data/tract_crime_counts_last12m.json` 的已验证元数据。
- 项目现有 Crime/UI/async/points 契约测试。

## Stages

- [x] Stage 1: 写入失败契约，锁定快照不可用时仍可选区，以及普查区事件刷新行为。
- [x] Stage 2: 最小化修复地图选择层与事件查询链路。
- [x] Stage 3: 完善状态提示并运行聚焦回归。
- [x] Stage 4: 构建、bundle policy、独占本地服务器和浏览器 smoke。
- [x] Stage 5: 最终 review、第一性原理复核和任务记录收尾。

## Acceptance criteria

- 快照关闭或日期不匹配时，普查区边界仍可见、可点击。
- 点击后 URL 写入合法 11 位 `tract` GEOID，并产生摘要和图表请求。
- 普查区模式会加载与多边形相交的事件点/明细，沿用当前时间和犯罪筛选。
- 固定快照覆盖匹配时，原有分级设色继续工作。
- 聚焦测试、构建、bundle policy 和浏览器 smoke 通过；无新增控制台错误。

## Non-goals

- 不实现任意时间窗口的全市普查区实时分级设色。
- 不新增住房、步行路线或综合安全指数。
- 不修改犯罪数据口径、分类体系或现有三色高亮上限。
- 不提交、推送或部署。

## Risks and constraints

- 当前单一 worktree 含大量用户及前序任务 WIP，必须只做窄范围增量修改。
- 普查区事件查询必须控制返回量并保持与现有事件列表的字段契约一致。
- Entry bundle 预算接近上限，优先复用现有 lazy Crime 模块和 SQL 工具。
