# Plan

## Goal

让用户选择 1–3 个具体犯罪类型后，地图中的对应事件点使用互不混淆、且来自当前分级设色配色方案的颜色高亮；筛选、摘要、地图、图例和共享 URL 表达同一组选择。

## Scope

- 保留默认“全部犯罪类型”视图和现有六个一级主题。
- 具体犯罪类型最多选择三项；达到上限时给出清晰、可访问的反馈。
- 选中项按稳定顺序绑定三种颜色，颜色随当前 `classPalette` 更新。
- 地图点、图例及当前选择说明同步展示类型与颜色。
- 保持现有分析计数和 SQL 筛选口径，不引入新的数据源或安全评分。
- 审查相邻的筛选、URL、地图和图例状态同步问题，只实现与本需求同根因且低风险的改进。

## Sources of truth

- `src/ui/panel.js` 与 `src/state/store.js`：筛选状态。
- `src/state/crime_view_state.js`：共享 URL 编解码。
- `src/routes_crime/`、`src/map/points.js`、`src/utils/sql.js`：Crime 点数据与 MapLibre 图层。
- `src/utils/classify.js`、现有 palette 控件与图例实现：配色契约。
- `scripts/tests/` 中现有 Crime、points lifecycle、UI 与 bundle 合同。
- 当前 dirty worktree 及 `docs/active/_worktree_registry.md`：所有既有 Help、i18n、Crime foundation WIP 必须保留。

## Acceptance criteria

- 选择一个具体犯罪类型时，该类型的地图点使用第一种 palette 高亮色。
- 选择两个或三个类型时，每类使用不同且稳定的颜色；不能选择第四项。
- 更换 palette 后，高亮颜色和图例同步变化，选择内容不丢失。
- 清空具体类型后回到现有默认点样式，不残留旧高亮或图例。
- URL 刷新恢复相同的最多三项选择和颜色顺序。
- 聚类、事件列表、摘要和图表继续使用同一份筛选数据；旧共享 URL 仍可读取。
- 无需新依赖，不提高 bundle 预算，不重启或停止用户拥有的 5173 服务。
- Buffer 模式地图点和事件列表只包含“半径圆内 ∩ 当前视口”的事件；拖图不再出现圆外事件。
- 时间范围改变后，具体类型列表与新窗口同步；仍有效选择保留，失效选择从状态与 URL 清除。
- 切换中英文时，当前分类图例无需重新查询数据即可立即翻译。
- 保留平台原生的普通点击及 Shift/Ctrl/Cmd 多选与取消行为；明确使用说明并继续限制最多三项。

## Non-goals

- 不增加第四种及以上并列颜色。
- 不改变犯罪分类版本、住宅稳定性公式、步行安全或外部数据模块。
- 不把颜色解释为严重程度、风险等级或预测结果。
- 不提交、推送、部署或修改其他 worktree。
- 不把事件点口径扩展为路线安全、预测风险或圆外“上下文事件”。

## Risks and constraints

- `fineSel` 是原生多选框；限制三项不能造成第四项短暂写入 URL 或触发错误请求。
- MapLibre 的 `match` 表达式必须有稳定 fallback，并兼容聚类/非聚类图层生命周期。
- palette 原本服务于分级设色；点高亮只能复用其色相，不得暗示同一数值等级。
- 当前工作树包含未提交的 Help、i18n 和上一阶段 Crime 改动，所有重叠编辑必须窄而可审查。
- 自定义修饰键交互不能破坏原生键盘操作、屏幕阅读器语义或移动端基本选择能力。
